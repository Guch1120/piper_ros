# 既存の FlexBE ステート実装を ROS 2 へ移行する際の注意点

ROS 1 から ROS 2 へのカスタム FlexBE ステートの変更の多くは、非常に最小限で済みます。これは、FlexBE のプロキシと組み込みの State クラスが、カスタムステートのプロセスのほとんどを舞台裏で処理しているためです。結果として、カスタム FlexBE ステートに対する最大の変更点は、FlexBE プロキシの設定と、ROS 1 の `rospy` パッケージへの直接呼び出しの処理に集中します。

次の画像は、FlexBE ベースのナビゲーションシステムである [Flexible Navigation](https://github.com/flexbe/flexible_navigation.git) の `TimedTwistState` の ROS 1 版（左）と ROS 2 版（右）を示しています。

![ROS1 vs. ROS2 state implementations](./timed_twist_state_conversion.png)

ROS 2 版のコンストラクタに見られるように、`TwistStamped` メッセージをパブリッシュするためのパブリッシャを作成するために使用される `ProxyPublisher` は、まず `TimedTwistState` のノードを使用して初期化する必要があります。
これは、サブスクライバ、アクションクライアント、サービスクライアントをそれぞれ作成するための `ProxySubscriberCached`、`ProxyActionClient`、および `ProxyServiceCaller` でも同様に行われます。
初期化後、プロキシパブリッシャ、サブスクライバ、アクションクライアント、およびサービスクライアントの作成は、ROS 1 と同様に行われます。
さらに、ROS 1 における以前のプロキシ関数呼び出しはすべて、ROS 2 でもサポートされています。
このため、ROS 1 と ROS 2 の間の変更のほとんどが隠蔽される FlexBE プロキシを使用することが推奨されます。

この点を踏まえると、残りの唯一の変更点は `rospy` パッケージへの直接呼び出しに関するものです。
それぞれの ROS 1 と ROS 2 のコードに示されているように、ヘッダーメッセージのタイムスタンプを設定するために、`rospy` と `TimedTwistState` のノードを使用しています。
タイムスタンプを設定する際、ROS 2 版ではコンストラクタ内の `TimedTwistStamped._node` とは対照的に、`self._node` を使用できています。
その理由は、コンストラクタでのカスタムステート作成時には、カスタムステートの個々のインスタンスはノードへのアクセス権を持っていないためです。
しかし、実行中にはカスタムステートのインスタンスはそのノードへのアクセス権を持っており、`TimedTwistState` はそのノードを使用して現在時刻を取得できます。
タイムスタンプのために時刻を取得するのと同様に、`rospy` パッケージを直接使用する各インスタンスは、カスタムステートのノードを使用するように変更する必要があります。

ROS 2 API の使用に関する詳細については、ROS 2 のドキュメントを参照してください。
